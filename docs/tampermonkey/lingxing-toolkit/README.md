# 领星油猴开发工具包

这个工具包解决一个明确问题：当领星 MCP 没有所需数据或操作时，让用户在自己已登录的领星页面中取得真实接口证据，再由 AI 基于统一请求层开发一个权限隔离的业务油猴插件。已经稳定并登记为 job capability 的业务插件，还可以通过本地桥接受 AI 的实时刷新任务。

它不是远程控制浏览器，也不是一个承载所有业务的“大插件”。

## 组成

- `dist/领星ERP-接口探针.user.js`：单纯用于记录真实接口证据。默认不显示面板、不安装网络 hook，也不记录请求；需要时从领星左侧导航的“探针”入口打开面板并手动开始，悬停可看到完整名称。请求列表支持全选、取消全选和部分选择提示。
- `lib/lingxing-page-client.js`：领星页面内部请求 SDK 源码。
- `dist/领星ERP-功能插件模板.user.js`：已内嵌固定版本 SDK 的安全模板，默认不可运行。
- `docs/领星油猴插件开发说明.md`：给 Codex、WorkBuddy 和其他 AI 的开发流程。
- `vendor/bridge-client.js`：本地自动化桥 v2 SDK 的固定副本。

探针、正式业务插件和任务 worker 职责不同：探针只记录证据；正式插件完成经过验证的具体业务；worker 只是正式插件的另一个触发入口，必须调用同一业务执行链。探针不得领取 AI 任务。

用户可见状态由每个正式业务插件自己负责，不再依赖公共“自动化中心”或统一注册。长期运行、定时运行或可由 AI 触发的插件，推荐仿照 FBA 数据桥：页面初始化后先延迟数秒，并等到原生“设置”项出现，再向领星左侧原生导航 `ul.el-menu[role="menubar"]` 插入自己的 `li.el-menu-item`。所有插件入口统一放在领星全部原生菜单之后，插件区内部按唯一的 `data-lx-tool-order` 升序排列；点击只切换本插件的状态面板。可见短名限制为两个中文或三个英文字母，完整名称放在 `title` 和无障碍标签里；导航收起时只显示图标，关闭面板后入口仍保留。每个插件必须使用唯一的入口 ID、标识、顺序号、短名和图标，并在领星 SPA/Vue 重绘导航后自动补挂载、校正到菜单末尾。

桥端 runtime heartbeat 可以作为内部诊断能力保留，但不是页面状态展示的前提，也不能替代插件自己的状态面板。AI 主动任务仍通过已登记的 job capability 工作，与是否存在公共状态中心无关。

## 构建和测试

```powershell
node .\scripts\build.cjs
node --test .\tests\*.test.cjs
```

最终插件自包含，不使用远程 `@require`，避免远程更新和缓存导致实际运行版本不可控。

## 安全边界

- 只匹配 `https://erp.lingxing.com/*`。
- 领星认证交给页面自己的请求客户端；SDK 不读取 Cookie、Token 或认证请求头。
- `$post`、`$gwPost`、`$gateAxios.get/post` 必须由业务适配器根据真实证据显式选择。
- 探针只保存证据，不自动重放、翻页、登记正式 Dataset 或执行写操作。
- 每项正式业务使用独立油猴插件、独立桥客户端和最小权限。
- AI 只能创建注册表中预先登记的 capability，不能把任意 endpoint、payload 或 JavaScript 交给插件执行。
- 本地桥不会启动浏览器或完成领星登录；任务 worker 只有在匹配页面已打开、插件启用且登录有效时才能领取任务。
- 已稳定的 FBA 导出插件保持独立，不作为公共宿主。
